# Solver-neutral implicit inverse baseline

> **Status: implemented and validated on 2026-09-02.** This page describes
> the low-dimensional frequency-domain inverse in `solvers/sdf_inverse/` and
> its MOD/Kress comparison driver. It does not replace the separate MOD-only
> neural B-scan adjoint.

## What is now working

[`run_sdf_inverse_comparison.py`](../run_sdf_inverse_comparison.py) can start
from a deliberately wrong circle SDF

```text
center = (0.48, 0.52) m, radius = 0.065 m
```

and recovers the analytic target

```text
center = (0.50, 0.50) m, radius = 0.050 m.
```

The observations are complex scattered fields from the independent analytic
penetrable-cylinder Mie series in `gpr_bem_ref`, not data generated by either
solver under test. MOD and Kress use the same implicit field, the same fitted ordered
curve at every objective evaluation, the same normalized frequency-domain
residual, the same parameter finite differences, the same bounds, and the
same damped Gauss--Newton/Levenberg--Marquardt policy. Only the forward-solver
dispatch changes.

This gives a small, auditable answer to two questions: can an incorrect implicit field
converge under the complete extraction/remeshing/forward pipeline, and how
does forward-solver error affect that recovery? It is intentionally not a
scalable neural inverse.

## Pipeline and ownership

```text
Torch implicit model (distance property optional)
  -> TorchImplicitField2D, negative inside
  -> marching-squares extraction and safeguarded level-set projection
  -> exactly one validated closed component
  -> Method-B Fourier fit and arc-length redistribution
  -> immutable even-node PeriodicCurve2D
       |                         |
       | unchanged curve        | copied points, normals, arc weights
       v                         v
  gpr_bem_kress             MOD boundary adapter
  full source x receiver    ImplicitBoundarySamples2D
  field -> paired diagonal  -> paired MOD field
       |                         |
       +------------+------------+
                    v
       normalized complex scattered-field residual
                    v
       bounded parameter finite differences + damped Gauss--Newton
```

The implementation is separated by responsibility:

- `solvers/sdf_inverse/geometry.py` performs the common SDF extraction,
  single-component validation, Method-B fit, and discretization. Its MOD
  adapter changes only the container and copies the ordered curve's nodes,
  normals, and periodic arc-length weights; it does not rebuild or compress a
  second geometry.
- `solvers/sdf_inverse/forward.py` owns the solver-neutral paired experiment
  and dispatch. MOD runs strict quadrature, direct unsquared Müller solve,
  analytic-extrapolated normal derivatives, NumPy, and complex128. Kress runs
  its native `PeriodicCurve2D` solve and explicitly selects the diagonal of
  its full source-by-receiver response.
- `solvers/sdf_inverse/models.py` supplies the exact three-parameter circle
  SDF, a rotated quadratic ellipse level set, a seeded topology-constrained
  random-feature neural implicit, and bounded Torch parameter controllers.
  The controller refuses an unexpectedly large parameter set rather than
  making full-network finite differences look practical.
- `solvers/sdf_inverse/optimization.py` owns the fixed complex-data objective,
  numerical Jacobian, damping, bound projection, backtracking, evaluation
  cache, accepted-iterate history, and explicit stop reason.

The residual normalizes each complex frequency column by the norm of the
observed column, applies optional frequency weights, and concatenates real and
imaginary parts for real least squares. This definition remains nonzero and
well-defined for one frequency; it does not use a one-point trapezoidal
frequency integral.

## Reproduce the comparison

Use the environment containing Torch, NumPy, and SciPy:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
NUMEXPR_NUM_THREADS=1 PYTHONPATH=solvers \
/home/drdeng/miniconda3/envs/EMNerf/bin/python \
  run_sdf_inverse_comparison.py \
  --output-dir results/inverse_solver_comparison/wrong-circle-mie-20260902 \
  --overwrite
```

By default the driver uses 12 paired ring observations, a `129 x 129`
extraction grid, an even 64-node ordered curve, a six-iteration cap, 0.25 and
0.5 GHz for fitting, and 1, 1.5, and 2.5 GHz only for holdout evaluation.
Useful controls are:

```text
--solvers mod kress
--initial-model circle|ellipse|random_features
--train-ghz 0.25,0.5
--holdout-ghz 1,1.5,2.5
--num-pairs 12
--num-nodes 64
--max-iterations 6
--loss-tolerance 1e-12
--output-dir PATH
--overwrite
--no-gate
```

The default output directory includes a UTC timestamp, so ordinary runs do
not overwrite one another. An explicitly named nonempty directory is refused
unless `--overwrite` is supplied; that option removes only this driver's known
artifact names. The checked dated bundle is
[`results/inverse_solver_comparison/wrong-circle-mie-20260902/`](../results/inverse_solver_comparison/wrong-circle-mie-20260902/).
It contains the full configuration and provenance in `metrics.json`, accepted
iterates in one trajectory CSV per solver, exact/initial/final responses and
geometry trajectories in compressed NPZ files, a convergence plot, and a
readable [`summary.md`](../results/inverse_solver_comparison/wrong-circle-mie-20260902/summary.md).
The driver exits nonzero when an enabled acceptance gate fails unless
`--no-gate` is supplied. Optimizer convergence is itself an acceptance gate,
not merely the reported stop label.

## Measured default result

| Solver | Train relative L2, initial -> final | Loss drop | Inverse holdout relative L2 | True-boundary holdout relative L2 | Center error | Radius error | Inverse wall time |
|---|---:|---:|---:|---:|---:|---:|---:|
| MOD | `9.737e-1 -> 2.713e-3` | `1.226e5x` | `7.044e-2` | `7.302e-2` | `< 0.0001 mm` | `0.0568 mm` | `~7.5 s` |
| Kress | `9.741e-1 -> 8.648e-11` | `1.294e20x` | `3.810e-10` | `8.195e-14` | `< 0.0001 mm` | `< 1e-8 mm` | `~4.5 s` |

Both accepted-loss histories were monotone, both center errors passed
`5e-4 m`, both radius errors passed `1e-3 m`, and maximum linear-system
relative residuals were below `1e-10`. That maximum covers every uncached
finite-difference and line-search forward, including rejected trials, plus
the initial, final, and true-boundary controls. Kress also passed the declared
holdout-beats-MOD gate. As a control, the driver evaluates both solvers on the
identical fitted boundary of the exact target SDF: MOD retains `7.302e-2`
holdout error while Kress reaches `8.195e-14`. The recorded initial- and
true-boundary node-coordinate parity deltas are exactly zero; the adapter
regression also verifies exact copies of normals and ordinary/strict weights.
This separates the forward discretization floor from any remaining inverse
parameter error. These
timings are one-run engineering measurements, not a formal hardware
benchmark.

The result demonstrates an important numerical effect. Both branches locate
the center, but the MOD forward discretization leaves a small fitted-radius
bias and a `7.0%` aggregate error on frequencies excluded from training.
Kress recovers the circle to the precision of this experiment and retains
near-numerical-precision holdout agreement. The comparison does not attribute
every timing difference to BIE assembly alone: its wall times include the
complete repeated SDF extraction, fitting, and objective evaluations. With
the same 42 inverse evaluations in the checked run, Kress was `1.67x` faster
by this end-to-end wall measure and its held-out error was `1.849e8x` lower.

## Non-circular and non-SDF initializations

Two additional checked cases keep the same analytic target, observations,
training/holdout split, geometry construction, and solver-specific controls:

| Initial field | Solver | Train relative L2, initial -> final | Holdout relative L2 | Final maximum circle error |
|---|---|---:|---:|---:|
| Rotated quadratic ellipse, non-SDF | MOD | `9.272e-1 -> 2.713e-3` | `7.044e-2` | `5.684e-5 m` |
| Rotated quadratic ellipse, non-SDF | Kress | `9.283e-1 -> 7.115e-10` | `3.225e-9` | `3.412e-11 m` |
| Seeded random-feature neural implicit, non-SDF | MOD | `9.298e-1 -> 2.713e-3` | `7.044e-2` | `5.684e-5 m` |
| Seeded random-feature neural implicit, non-SDF | Kress | `9.298e-1 -> 3.696e-10` | `3.645e-9` | `5.003e-11 m` |

The ellipse starts with semi-axes `0.072/0.038 m`, a `0.4 rad` fixed rotation,
and a dimensionless quadratic field rather than a distance value. The neural
case uses four fixed seeded tanh features with a trainable output head, center,
and base radius. Its bounded radial envelope guarantees one positive
star-shaped contour throughout every trial. Both cases passed all 25 gates;
see the consolidated
[`results/inverse_solver_comparison/README.md`](../results/inverse_solver_comparison/README.md).

For generic implicit fields, raw `|F|` is not a geometric error because
multiplying the field by a constant changes it without moving the zero set.
The pipeline therefore records the scale-aware `|F| / ||grad F||` curve
residual as well. Tests also verify that both added fields have materially
non-unit boundary gradients and materially non-circular initial contours.

## What was repaired in the legacy MOD inverse

The existing `run_ibim_circle_inverse_bscan.py` remains a separate MOD-only
neural/adjoint pipeline. Its audit found four concrete reliability problems:

- the canonical driver passed an unsupported `min_boundary_samples` keyword;
- a CUDA-capable Torch installation selected CuPy assembly without checking
  that CuPy could actually be imported;
- any adjoint shape-gradient exception silently selected a sparse finite-
  difference fallback; and
- the inverse smoke test used one frequency, for which the trapezoidal
  frequency weight was zero and the nominal B-scan objective was degenerate.

The unsupported keyword was removed. Backend resolution now requires both
Torch CUDA availability and an importable CuPy package, otherwise assembly
uses NumPy. The shape-gradient policy now defaults to `error`; finite
differences are available only through the explicit `finite_difference`
policy, and every iteration records the method used. The smoke test now uses
two frequencies and asserts a finite, nonzero objective and dual. These are
hardening fixes, not evidence that the legacy random-SIREN benchmark now has
the accuracy guarantees of the new circle-parameter comparison.

## Scope and limitations

- The common domain is one smooth, simple, closed, regular component with a
  negative-inside implicit sign. Missing, open, boundary-touching, multiple,
  self-intersecting, or non-regular zero sets fail explicitly; there is no
  component-selection or representation fallback.
- Marching squares can emit adjacent duplicate vertices when a zero contour
  lies exactly on grid nodes. The front end removes only those consecutive
  near-duplicates before polygon validation; non-adjacent repeated geometry
  is still rejected as a genuine degeneracy.
- Because Kress is one of the compared forwards, the shared run currently
  uses an even node count, separated source/receiver points, nonmagnetic media
  (`mur=1`), and lossless media (`sigma=0`). Corners, holes, nested materials,
  and multiple components are outside this baseline.
- The extraction box is `((0.30, 0.30), (0.70, 0.70)) m`, wide enough to
  contain every allowed center/radius trial with at least `0.01 m` clearance.
- Finite differences operate on the complete black-box parameter-to-field
  map, so extraction and remeshing are included. They scale as at least two
  forward evaluations per parameter per Jacobian. The checked models have
  three, four, and seven controls; this is useful for validation, not training
  thousands of SIREN weights.
- A randomly initialized SIREN need not contain exactly one usable closed zero
  contour. Before it can enter this pipeline it needs a topology-valid
  initialization or pretraining contract. Even then, parameter finite
  differences are not a viable optimizer for a full network. A deterministic
  unconstrained random-MLP regression confirms that such a field is rejected
  during contour validation before either BEM forward is called.
- `gpr_bem_kress` remains forward-only. Its retained `A`, `C=[D,-S]`, state,
  and receiver data expose an adjoint seam, but there is no Kress operator
  adjoint, shape derivative, or autograd path. A scalable neural inverse needs
  derivatives of the actual weighted Kress blocks, incident field, receiver
  map, points, normals, speeds, source Jacobians, and diagonal split, together
  with finite-difference gradient acceptance tests.
- Kress remains outside `solver_select`; the new comparison imports both peer
  packages directly. `run_ibim_circle_inverse_bscan.py --solver=mod` still
  names the maintained legacy adjoint path.

The next credible milestone is therefore not to remove the low-dimensional
baseline. It is to use it as the oracle for a Kress discrete-adjoint and
topology-controlled neural coupling, then require both parameter-level and
directional-gradient agreement before scaling the number of SDF parameters.
