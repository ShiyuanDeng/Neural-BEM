**Repository:** `ShiyuanDeng/Neural-BEM`  
**Branch:** `feature/ordered-boundary-nystrom`  
**Baseline head when this plan was written:** `f5a77ff18f8af6def6609c5e0bbbce039db06b23`

---

## 1. Objective

Build the smallest credible topology-capable extension of the existing **Explicit Radial Fourier** inverse.

The first target capability is deliberately narrow:

> Starting from an accepted reconstruction containing **one radial-Fourier component**, while the measured data were generated by **two separated, same-material dielectric components**, use a **current-domain topological derivative** to identify the missing component, add it as a new radial-Fourier component, verify that the actual data objective decreases, and then resume the existing radial coefficient inverse with both components.

The intended architecture is

\[
\boxed{
\text{fixed-topology radial refinement}
\;\longleftrightarrow\;
\text{topological-derivative component birth}
}
\]

with a canonical state

\[
\mathcal C
=
\{C_1,\ldots,C_M\},
\]

where every \(C_m\) is the existing `RadialFourierCurveState`.

For the initial study, **only component birth is in scope**. Do not implement merge, split, deletion, holes, nesting, touching components, unknown per-component materials, or MLP fitting.

---

## 2. Why this is the right first topology experiment for this repository

The current radial route is already a clean fixed-topology parametric inverse:

```text
initial contour
  -> one-time radial Fourier projection
  -> authoritative RadialFourierCurveState
  -> direct radial curve
  -> Kress/MOD forward
  -> finite-difference coefficient Jacobian
  -> damped coefficient step
  -> accepted radial state
```

The important existing facts are:

1. A single `RadialFourierCurveState` is structurally one positive star-shaped component. Continuous coefficient updates cannot change the number of components.
2. The accepted geometry is already independent of the MLP. Do not bring the MLP back into this experiment.
3. The repository already has an opt-in multi-component Kress/Müller forward in `solvers/gpr_bem_kress/multicomponent.py`.
4. That forward supports **disjoint, non-nested, same-interior-material components** and rejects components that are too close for the current ordinary cross-component quadrature.
5. The existing radial route already has the fixed-topology optimizer needed for the shape-refinement half of the hybrid method. The first topology study should not replace it merely because the reference literature uses IRGN.

This makes the cleanest research question:

> Does a mature topological-sensitivity mechanism provide the missing **object-count update**, while the existing radial inverse continues to own ordinary smooth shape updates?

# 3. Literature practice to preserve

The implementation should be explicitly inspired by the mature **topological derivative + star-shaped/Gauss–Newton** inverse-scattering lineage, but adapted to the repository rather than copied mechanically.

## 3.1 Topological derivatives are topology events, not ordinary per-step shape gradients

Carpio, Dimiduk, Le Louër and Rapún (JCP 2019) use:

1. topological sensitivity to obtain or modify the number of components;
2. star-shaped spectral parameterizations for accurate shape correction;
3. regularized Gauss–Newton while the fixed-topology inverse is progressing;
4. a fresh topological-derivative computation when the fixed-topology cost stagnates before the stopping criterion is met;
5. a restart of the smooth parametric inverse after the topology has been modified.

That separation should remain visible in this code.

For this repository:

- **radial coefficient optimizer** = fixed-topology shape correction;
- **topological derivative** = discrete component-birth proposal;
- do **not** differentiate through the topology event.

A topology event creates a new accepted state and the fixed-topology optimizer restarts from that state.

---

## 3.2 After an object already exists, use the topological derivative of the **current domain**

This is essential.

A one-step free-space imaging formula answers:

\[
\text{“where should the first object be inserted into empty background?”}
\]

The core experiment instead asks:

\[
\text{“given the current object } \Omega_k,
\text{ where should additional material be inserted?”}
\]

The iterative topological-sensitivity literature explicitly recomputes

\[
D_T J(x;\Omega_k)
\]

using the **forward and adjoint fields for the current approximate domain**.

Do not compute a free-space indicator after the first component is present and call it an iterative topological derivative.

The first benchmark is intentionally designed to make this distinction unavoidable:

```text
truth:      component A + component B
current:    component A only
question:   does D_T J(x; component A) locate missing component B?
```

---

## 3.3 Threshold strong favorable topological regions, then identify connected components

A common literature rule is a relative threshold of the form

\[
\Omega_{\mathrm{TD}}
=
\left\{
x:
D_TJ(x)
<
(1-C_0)
\min_y D_TJ(y)
\right\},
\qquad 0<C_0<1,
\]

when negative \(D_TJ\) means inserting material decreases the objective.

In the 2019 hybrid paper, representative values included \(C_0=0.15\) and \(0.2\), and tests also explored nearby values. These numbers are **not universal physical constants**.

Implementation requirements:

- make `C0` configurable;
- use one declared default for the first experiment, suggested `0.15`;
- do not tune `C0` from the known target geometry or holdout data;
- save the raw TD field, threshold value and binary mask;
- label connected components of the thresholded mask;
- preserve the global minimum location separately from the threshold mask.

The literature often refines the topological field on a finer local grid around detected regions. A coarse-to-fine implementation is encouraged if it is simple, but it is secondary to validating the derivative itself.

---

## 3.4 Fit a star-shaped representation only **after** topology detection

The literature typically:

1. thresholds the topological field;
2. extracts connected regions;
3. computes component centroids;
4. fits one star-shaped spectral representation per connected component;
5. restarts the smooth optimizer.

For this first repository experiment, use a deliberately simpler version:

- use the TD connected component to propose the new component centre;
- initialize the new component as a **circle** (`K=1`, i.e. centre + mean radius only);
- estimate its seed radius from the threshold region, for example using equivalent area

\[
r_{\mathrm{eq}}
=
\sqrt{\frac{A_{\mathrm{mask}}}{\pi}};
\]

- allow a small backtracking sequence on the radius if needed;
- after the birth is accepted, let the ordinary radial optimizer change centre/radius and later higher modes.

This is a deliberate first-pass simplification. Do not spend the initial task implementing a complicated binary-mask-to-Fourier contour fitter.

A later version may project the detected TD component itself into a higher-order radial Fourier state, which more closely follows the 2019 procedure.

---

## 3.5 A topology proposal is accepted by the **actual forward objective**

The TD is an asymptotic indicator. It is not permission to commit an arbitrary finite-size new object.

Published hybrid procedures choose topology thresholds/updates so that the cost decreases. Follow the same principle more explicitly:

```text
TD field
  -> candidate region
  -> candidate radial component
  -> full multi-component Kress solve
  -> actual fixed training objective
  -> accept/reject
```

Never accept a new component solely because \(D_TJ<0\).

If the first proposed radius does not decrease the actual objective, backtrack its radius. If no valid radius produces a decrease beyond numerical repeatability, record a failed birth proposal and stop that arm. Do not force topology change.

---

## 3.6 Restart the smooth optimizer after a topology event

The literature restarts the parametric inverse after modifying the object configuration.

Do the same here.

After an accepted birth:

- commit the new `MultiRadialFourierState`;
- reset any damping/trust-region/line-search state that logically belongs to the previous parameter dimension;
- rebuild parameter offsets;
- recompute the fixed-topology Jacobian from the new state;
- preserve the component identities;
- start a new optimization stage.

Do not carry a Jacobian or controller state across a change in parameter dimension unless there is a mathematically justified mapping.

---

## 3.7 Keep raw physical TD and multifrequency proposal normalization distinct

Multifrequency topological-imaging papers commonly normalize single-frequency indicators before combining them so that one frequency does not dominate merely because of scale. A representative construction is

\[
I_{\mathrm{TD}}(x)
=
\frac{1}{N_f}
\sum_f
\frac{D_{T,f}(x)}
{\left|\min_y D_{T,f}(y)\right|}.
\]

For this project maintain **two quantities**:

### Raw objective derivative

\[
D_TJ_{\mathrm{raw}}(x)
=
\sum_f D_{T,f}(x)
\]

with exactly the same data weights and normalization as the training objective. This is the quantity used for derivative/asymptotic validation.

### Proposal indicator

An optionally frequency-normalized field used only to localize candidate regions.

Do not claim a normalized imaging indicator is literally the derivative of the original summed objective unless it is.

Every result must state which field was used for localization.

---

## 3.8 Noise-dependent stopping rules from the literature are not directly reusable in the noiseless first benchmark

The 2019 hybrid algorithm uses a Morozov discrepancy principle and, in its noisy setting, triggers topology modification when the cost stagnates while the residual remains inconsistent with the noise level. Their reported implementation used \(\tau=1.01\) for the discrepancy principle.

The first repository benchmark is noiseless, so do **not** manufacture a fake \(\delta\) merely to reproduce that formula.

For the initial study use a deterministic sequence:

1. establish the current radial state;
2. compute the TD once;
3. attempt one birth;
4. refine the resulting multi-component state.

Only after that works should an automatic stagnation-triggered state machine be added.

# 7. Proposed state model

Introduce an explicit multi-component radial state, either as a small new dataclass or a similarly strict immutable structure:

```text
MultiRadialFourierState
    components: tuple[RadialFourierCurveState, ...]
```

Requirements:

1. At least one component.
2. Unique persistent `component_id`s.
3. Deterministic component order.
4. Do not reorder components by centroid after every trial.
5. Each component independently preserves the existing radial gauge:
   - explicit Cartesian centre;
   - mode-one radial coefficients fixed to zero;
   - positive-radius certificate.
6. The combined forward geometry is built by:
   - `radial_fourier_state_curve(component_i, ...)` for every component;
   - one `OrderedBoundary2D` containing those curves;
   - the existing multi-component Kress path.
7. Validate the combined topology using the existing multi-component clearance/non-nesting checks before solving.
8. A topology event appends a new component with a new stable ID.
9. The initial version never mutates an existing component merely because a TD mask was rasterized.

That last point is a deliberate adaptation from the literature. Published algorithms may reconstruct/refit all contours from the modified topological region. Here the existing radial curves are already canonical numerical states. For a **disjoint birth**, preserve them exactly and add only the new component. This avoids introducing unrelated projection drift.

# 8. Mathematical target for the 2-D TMz topological derivative

## 8.1 Definition to validate

For a current reconstruction \(\Omega\) and a point \(z\) in the exterior, insert a small disk \(B_\rho(z)\) made of the same material as the existing inclusions.

Use the 2-D area scaling

\[
J(\Omega\cup B_\rho(z))
=
J(\Omega)
+
\pi\rho^2 D_TJ(z;\Omega)
+
o(\rho^2).
\]

Therefore the direct numerical validation quantity is

\[
Q_\rho(z)
=
\frac{
J(\Omega\cup B_\rho(z))-J(\Omega)
}{
\pi\rho^2
}.
\]

A correct implementation must produce

\[
Q_\rho(z)\rightarrow D_TJ(z;\Omega)
\]

over a resolved range of decreasing \(\rho\).

---

## 8.2 Expected field-product structure

For the current repository's lossless, nonmagnetic dielectric TMz transmission problem, the principal differential coefficient is unchanged when only permittivity changes. Therefore the topological derivative should reduce to a local product of:

- the **current total forward field** at \(z\);
- an **adjoint/residual backpropagated field** at \(z\);
- the interior/exterior wavenumber-squared contrast.

For one frequency, the expected structure is of the form

\[
D_TJ(z;\Omega)
\sim
-\operatorname{Re}
\left[
\left(k_i^2-k_e^2\right)
\sum_s
u_s(z)\,a_s(z)
\right],
\]

where \(a_s(z)\) is built from the data residuals for source \(s\) and the Green/total response of the **current domain** from receiver locations to \(z\).

The exact:

- sign;
- conjugation;
- factor of \(1/2\);
- residual normalization;
- source-strength factor;
- frequency/data weighting;

must be derived from the repository's actual objective and time/Hankel convention.

**Do not regard the displayed sign as accepted until the finite-radius insertion test passes.**

A useful reciprocity-based implementation for a quadratic complex residual is expected to have the structure

\[
a_s(z)
=
\sum_r
w_{sr}\,
\overline{r_{sr}}\,
G_\Omega(z,x_r),
\]

where \(G_\Omega\) is the current-domain total Green response for a unit exterior source at receiver \(x_r\). This may allow the TD field to be assembled using the existing multi-component forward machinery with receiver positions reused as source locations, rather than requiring a multi-component shape adjoint.

Again, derive this carefully from the actual residual convention before committing it.

---

# 10. Phase 1 — current-domain TD diagnostic

This is the first real deliverable.

## 10.1 Core benchmark

Construct the simplest discriminating scene:

```text
truth:
    two well-separated same-material circles A and B

current reconstruction:
    circle A only
    A is initially exact, or as close to exact as the current radial representation allows

unknown to the inversion:
    circle B
```

Why make A exact first?

Because this removes ordinary shape error as a confound. The residual is then dominated by the missing component and its multiple-scattering interaction with A.

Use:

- the existing physical material settings;
- a current validated acquisition;
- the same objective conventions used by the radial inverse;
- a search region fully containing B;
- enough component separation to be comfortably within the current multi-component Kress clearance regime.

Prefer an existing validated two-component scene if one already exists in the repository. Otherwise create a new clearly documented synthetic two-circle scene.

The first run may generate observations with the same multi-component Kress solver, but it must be labelled a **self-consistency topology experiment**, not independent forward validation.

---

## 10.2 Evaluate the TD on an exterior inspection grid

Add a configurable grid, for example:

```text
td_grid_shape = (129, 129)
td_bounds = current physical search bounds
```

The exact default may be adjusted to existing project conventions.

Mask out:

- points inside the current components;
- a clearance buffer around current component boundaries;
- points too close to sources/receivers;
- points that could not host even the minimum candidate circle while respecting the multi-component Kress clearance rule.

For every valid grid point and active frequency:

1. evaluate the current total forward fields for the training sources;
2. construct the residual-weighted adjoint/backpropagated field;
3. evaluate the raw \(D_{T,f}J(z;\Omega)\);
4. save all per-frequency fields before aggregation.

Do not threshold yet.

---

## 10.3 Empty-domain sanity check

Before trusting the current-domain result, add a simpler special case:

```text
current = empty background
truth = one small circle
```

Where practical, compare the implemented expression with the known free-space formula implied by the same derivation.

This is a sanity check, not the main topology benchmark.

# 11. Phase 1B — finite-radius insertion validation

This is a hard gate.

Select several probe locations:

1. the TD global minimum;
2. the true missing-object centre, if different;
3. a background point with modest TD magnitude;
4. optionally a point with positive/unfavorable TD.

For each point \(z\), create a sequence of small valid circular insertions:

\[
\rho_1>\rho_2>\rho_3>\cdots
\]

that are:

- small enough to approach the asymptotic regime;
- large enough to be numerically resolved;
- separated enough from current components;
- individually refined if necessary to ensure the observed trend is not a node-count artifact.

Compute

\[
Q_\rho(z)
=
\frac{
J(\Omega\cup B_\rho(z))-J(\Omega)
}{
\pi\rho^2
}.
\]

Report:

- \(D_TJ(z;\Omega)\);
- every \(Q_\rho(z)\);
- relative error;
- sign agreement;
- whether a convergence window appears as \(\rho\downarrow0\);
- the forward node resolution used for every insertion.

### Gate

Do not implement automatic birth until:

- the strong nonzero probes have the correct sign;
- at least one resolved decreasing-radius sequence visibly approaches the TD prediction;
- the TD ranking distinguishes favorable and unfavorable probes;
- there is no unexplained sign flip under forward refinement.

A desirable numerical target is about 10% relative agreement at a strong probe over the resolved asymptotic window; an error larger than about 20% without a clear convergence trend is a stop-and-diagnose result, not permission to tune the birth threshold.

# 13. Phase 2 — one birth proposal

Only after the TD derivative and localization gates pass.

## 13.1 Build the proposal mask

Use the declared threshold

\[
D_TJ(z)
<
(1-C_0)
\min D_TJ,
\]

or the analogous rule on the explicitly labelled proposal indicator.

Suggested first default:

```text
C0 = 0.15
```

Do not tune from truth.

Extract connected components of the threshold mask.

Reject regions that:

- intersect the current geometry;
- enter the forbidden Kress clearance buffer;
- touch the search-domain boundary;
- are too small to be resolved;
- are too close to sources/receivers.

For the initial experiment, choose the valid connected region containing the global favorable minimum. Do not attempt simultaneous birth of multiple objects yet.

---

## 13.2 Convert the TD region to a new radial component

For the first pass:

```text
new centre = centroid of the selected TD region
new radial mode = K1 circle
new radius = equivalent-area radius of the selected region
```

Give it a persistent new component ID such as:

```text
td_birth_001
```

Build the corresponding `RadialFourierCurveState`.

Do not refit the already accepted components.

---

## 13.3 Birth line search / actual-loss acceptance

The TD is asymptotic, so the full threshold-region radius may be too large.

Evaluate a small declared scale sequence, for example:

```text
1.0 * r_eq
0.75 * r_eq
0.50 * r_eq
0.35 * r_eq
```

or an equivalent backtracking rule.

For each proposal:

1. build the new `MultiRadialFourierState`;
2. construct all radial curves;
3. construct `OrderedBoundary2D`;
4. run the existing topology/clearance validation;
5. solve the actual multi-component Kress forward;
6. evaluate the unchanged training objective.

Accept only a candidate satisfying

\[
J_{\mathrm{new}}
<
J_{\mathrm{old}}
-
\text{numerical acceptance margin}.
\]

Set the acceptance margin from measured forward repeatability/numerical noise, not an arbitrary large percentage.

Record every rejected proposal and reason.

If none passes, the result is `no_acceptable_birth`. Do not silently move the centre to the truth or alter `C0` until one works.

# 14. Phase 3 — multi-component radial refinement

Only after a TD-guided birth is accepted by the actual objective.

## 14.1 Reuse the existing optimizer

Generalize the fixed-topology radial parameter vector to the concatenation

\[
p
=
\begin{bmatrix}
p_1\\
\vdots\\
p_M
\end{bmatrix},
\]

with persistent block offsets for each component.

For the first two-circle case use `K=1` for both components unless the current implementation makes another minimum mode more natural.

The finite-difference objective evaluation must:

```text
perturb one radial coefficient
  -> rebuild only the candidate state logically affected
  -> reconstruct all component curves
  -> form OrderedBoundary2D
  -> solve full multi-component Kress problem
  -> return the same residual vector
```

Cross-component multiple scattering must therefore be included automatically in every Jacobian column.

Do not create a new shape adjoint for this initial study.

---

## 14.2 Geometry validity

Every candidate multi-radial update must preserve:

- positive radius for every component;
- valid periodic curves;
- physical bounds;
- no self-intersection;
- no component intersection;
- no nesting;
- minimum cross-component clearance required by `gpr_bem_kress.multicomponent`.

A trial violating these rules is an invalid geometry step and must be rejected, not repaired by silently moving components.

---

## 14.3 Component identities

The optimizer must never infer parameter correspondence by sorting current centroids.

Use stable component IDs and stable parameter slices.

Example:

```text
component_A:
    centre_x, centre_y, radius, ...

td_birth_001:
    centre_x, centre_y, radius, ...
```

This matters for finite differences, histories and later topology events.

# 15. Initial experiment sequence

Do not begin with a fully automatic unknown-topology loop.

Run this staged sequence.

## T0 — TD formula sanity: empty background -> one circle

Purpose:

- basic sign/conjugation/prefactor sanity;
- finite-radius insertion asymptotics.

No claim about iterative unknown topology.

## T1 — core current-domain TD: exact A -> truth A+B

Purpose:

- demonstrate that \(D_TJ(x;A)\) detects B;
- validate against small-circle insertions in the presence of existing A.

This is the most important first result.

## T2 — actual birth

Use T1's TD field to propose B.

Gate:

- new component obtained without target information;
- actual training objective decreases;
- multi-component geometry passes all guards.

## T3 — two-component radial refinement

Resume radial optimization after accepted birth.

Track:

- both centres;
- both mean radii;
- field loss;
- holdout loss;
- component clearance;
- accepted/rejected coefficient steps.

## T4 — only after T0–T3 work: wrong A + missing B

Now initialize A with a controlled centre/radius error.

Purpose:

- test interaction between ordinary shape error and topology discovery.

Do not jump to a star/ellipse/multiple-birth target before this.

# 16. Multifrequency protocol

The first derivative validation should be performed at **one frequency** to make sign and scaling interpretable.

Then repeat the localization experiment with the intended training frequency set.

For every frequency \(f\), save:

- \(D_{T,f}\);

# 20. Decision gates

| Gate | Pass condition | If it fails |
|---|---|---|
| **G0: forward reuse** | multi-component forward passes existing/refinement checks | stop; topology experiment is not interpretable |
| **G1: TD asymptotics** | finite-radius insertion quotients approach TD with correct sign on strong probes | fix derivation/conventions; do not tune threshold |
| **G2: localization** | current-domain TD puts a strong favorable basin at the missing object | study acquisition/frequency/indicator; do not add geometry heuristics |
| **G3: birth acceptance** | TD-derived finite component strictly reduces actual training objective | diagnose finite-size proposal/threshold; do not force birth |
| **G4: post-birth refinement** | existing radial optimizer can improve the accepted multi-component state | diagnose multi-radial optimization separately |
| **G5: robustness** | wrong-A + missing-B case still discovers B without truth-guided tuning | then consider automatic topology triggers |
| **G6: extension** | only after G0–G5 | consider deletion, repeated births, merge/split handling |

A failure at one gate should not be relabelled as failure of every layer.

# 21. Failure interpretation

## TD formula fails insertion asymptotics

Likely causes:

- conjugation error;
- sign convention error;
- missing \(k_i^2-k_e^2\) factor;
- wrong objective normalization;
- residual weights do not match the production objective;
- adjoint/backpropagated field not computed for the current domain;
- source-strength factor omitted;
- insertion radius not in a resolved asymptotic regime.

Do not change `C0`.

## TD is mathematically correct but misses B

Likely causes:

- acquisition does not localize that component;
- frequency too low/high;
- multiple-scattering interference;
- aperture limitation;
- inappropriate multifrequency aggregation.

This is a physics/information result.

## TD localizes B but finite birth increases objective

Likely causes:

- asymptotic direction is correct but candidate is too large;
- threshold region overestimates size;
- candidate violates interaction assumptions;
- multiple finite candidates should be line-searched.

Backtrack radius before changing the TD formula.

## Birth works but radial refinement fails

This isolates a multi-component parametric optimization problem. Do not blame topology detection.

## Components approach the clearance guard

Record this as an unsupported close-interaction/merge regime. Do not relax the Kress guard merely to continue.

# 22. What the first successful result would establish

A successful T0–T3 sequence would justify the following narrow statement:

> The existing explicit radial-Fourier inverse can be extended from fixed one-component geometry to unknown separated object count by using a validated current-domain topological derivative to propose a new component, while retaining radial Fourier coefficients as the geometry authority and the existing coefficient optimizer for fixed-topology refinement.

It would **not** establish:

- arbitrary topology;
- general split/merge handling;
- nested objects or holes;
- close/touching objects;
- unknown materials;
- noisy robustness;
- GPR half-space performance;
- independent forward-model validation;
- superiority over an implicit/level-set topology method.

Keep those claims separate.
